# Meridian 59 (Server 900) — Infrastructure

## Overview

Two environments mirror each other: **production** (server 900, always-on) and **dev** (spun up on demand via Terraform).

Each environment runs two droplets:
- **Game server** — blakserv binary + HTTP maintenance bridge
- **Web server** — FastAPI identity portal + MariaDB


## Maintenance Bridge Protocol

The bridge (`webapi/bridge/bridge.py`) translates HTTP to the blakserv raw TCP maintenance protocol:

```
POST /execute
{"command": "getplayercount"}
→ {"output": "..."}
```

`M59Client` in `webapi/app/core/m59.py` speaks HTTP to this bridge. Set `M59_MAINTENANCE_PORT=9999` (bridge port) not `9998` (raw blakserv port) in the web server `.env`.

## Updating the Game Server

```bash
scripts/deploy_dev_gameserver.sh        # dev
# prod: manually rsync artifacts + systemctl restart blakserv
```

The deploy script downloads the latest `meridian_server` (Windows build, contains all data files) and `blakserv-linux` artifacts from GitHub Actions, then rsyncs to the server. The Linux binary overwrites whatever the Windows build included.

## Updating the Web API

```bash
scripts/deploy_dev_webapi.sh            # dev
# prod: git -C /opt/m59-account-api pull && systemctl restart m59-webapi
```

## Google OAuth

Shared credentials used for both prod and dev. Authorized redirect URIs must include both `https://www.emfiftynine.info/auth` and `https://dev.emfiftynine.info/auth` in the Google Cloud Console.

`FORCE_HTTPS=1` in the `.env` corrects the callback URL when running behind a proxy (nginx) that receives HTTP internally.
